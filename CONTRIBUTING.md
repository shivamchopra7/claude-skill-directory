# Contributing to Claude Skill Directory

Thanks for your interest in contributing!

This is a single self-contained repository. Discovery, download, deduplication,
security scanning, index generation, the published site, and the archived skill
tree all live here, so every change lands in one place.

## How to Submit a New Skill

### Option 1: Open an Issue (Recommended)

Open an [issue](https://github.com/shivamchopra7/claude-skill-directory/issues/new) with the following info:

- **Name**: Skill name (kebab-case)
- **Repository**: GitHub URL of your skill repo
- **Description**: One-line description
- **Category**: e.g. `development`, `devops`, `productivity`, `data`, `design`, `testing`
- **Tags**: Relevant keywords

We'll review and add it to the directory.

### Option 2: Pull Request

Open the PR against `shivamchopra7/claude-skill-directory` and edit
`sources/community.json`:

```json
{
  "name": "your-skill-name",
  "repo": "owner/repo",
  "path": "",
  "description": "One-line description of your skill.",
  "category": "development",
  "tags": ["tag1", "tag2"],
  "stars": 0
}
```

## Generated vs Hand-Owned Paths

Most of the repository is build output. These paths are regenerated by the
pipeline and must not be hand-edited — edits are overwritten on the next run:

- `skills/**`
- `registry.json`, `registry_summary.json`, `registry-manifest.json`, `registry-shards/**`
- `docs/search-index*`, `docs/search-shards/**`
- `docs/quality-index*`, `docs/quality-shards/**`
- `docs/security-index*`, `docs/security-shards/**`
- `docs/ranking-index*`, `docs/ranking-shards/**`
- `docs/categories/**`, `docs/stats.json`, `docs/featured.json`, `docs/plugins.json`
- `THIRD_PARTY_NOTICES.md`

Hand-owned paths — where fixes actually belong:

- `scripts/`, `crawler/` — pipeline logic
- `sources/` — skill source lists
- `schema/`, `taxonomy/` — validation and category definitions
- `docs/index.html`, `docs/css/`, `docs/js/`, and the Markdown files under `docs/`
- `.github/workflows/` — automation
- `supabase/schema.sql` — schema changes (files under `supabase/migrations/` are already applied and are immutable)
- Root documentation: `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`

## How to Correct an Existing Archived Skill

Content under `skills/**` is generated from upstream sources, so a direct edit
there is overwritten on the next refresh. To get a correction to stick:

1. Send the fix upstream to the skill's own repository, which is recorded in the
   skill's `metadata.json` as `source_url`. The next archive refresh picks it up.
2. If the problem is in how this pipeline imports, classifies, or renders the
   skill, open an issue or PR against the relevant script under `scripts/` or the
   source entry under `sources/`.

Reports are welcome even without a fix. Open an issue with the skill path and
what is wrong, and it will be routed to the right place.

## Requirements

- Your repo must contain a valid `SKILL.md` file (root or subdirectory)
- Must have an open-source license (MIT, Apache-2.0, etc.)
- No malicious code or credential harvesting

## Pipeline Invariants

Changes to the archive layout must preserve these rules:

- **No paths may differ only by case.** Many contributors are on
  case-insensitive filesystems, and colliding paths corrupt checkouts.
- Use `normalize_name()` and `ensure_unique_dir()` for all skill directory
  creation.
- Directory conflict suffix policy must match `scripts/utils.py`:
  - Prefer the repo suffix: `{name}-{owner}-{repo}` (via `get_repo_suffix()`).
  - Fall back to `{name}-{short-hash}` when the repo suffix is unavailable.
  - Append numeric disambiguators if still needed: `-2`, `-3`, ...
- Reuse an existing directory when the metadata key resolves to the same skill.
- Never delete skills to resolve a conflict; **rename** with suffixes instead.
- Backward compatibility for historical directory names is not required. Prefer
  deterministic, conflict-free paths.

## Canonical Layout

Archived skills use a category-at-root layout:

```
skills/<category>/<skill>/SKILL.md
skills/<category>/<skill>/metadata.json
```

Canonical category slugs live in `taxonomy/categories.yaml`. Validate with
`python scripts/check_taxonomy_governance.py`.

Design notes and specifications live under [`docs/`](docs/).
